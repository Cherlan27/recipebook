=== Backend Strategy

* FastAPI with a layered structure (`app/api/routes`, `app/core`, `app/db`, `app/models`) — separates routing, configuration, database access, and domain models from the start, so follow-up issues (e.g. recipe CRUD) can slot in instead of requiring a restructure (see ADR-6).
* Database access via SQLAlchemy 2.0 in **async** mode (driver `aiosqlite`), since FastAPI itself is async — synchronous DB calls would block the event loop. The extra effort compared to sync SQLAlchemy is small on a greenfield project (see ADR-1 in <<section-design-decisions>>).
* A real engine/session is set up already in the scaffold, rather than just touching a file, so later issues can add models/queries directly.
* The database schema is managed by versioned **Alembic migrations** that run automatically at application start — locally and in the container alike. If the database file already exists and migrations are pending, a copy `app.db.bak-<revision>` is written next to it first; a failing migration prevents startup (see ADR-8).
* Integrity rules of the data model (unique recipe numbers, value ranges, link cascades, case-insensitive tag names) are enforced by the database itself, not only by the ORM.

=== Frontend Strategy

* Vue 3 with TypeScript and the Composition API (`<script setup>`) instead of the Options API — better type inference, logic grouped by feature rather than by option type (see ADR-2).
* No state management (Pinia) in the scaffold — introduced only once a feature needs real cross-component state, most likely the recipe list (see ADR-3).

=== Development Tooling

* Root `Makefile` with targets `backend`, `frontend`, and `dev` (starts both servers in parallel) as a single local entry point (see ADR-4).

=== Deployment Strategy

* Single container: a multi-stage build compiles the frontend and copies it into the Python runtime image, where the backend serves it as static files alongside the API on one published port — same origin, no CORS needed in this environment (see ADR-7).
* Built directly on the target device from source, not pushed to a registry, keeping the project independent of external services (see ADR-7).
* Application data (the SQLite file) lives in a bind-mounted host directory so it survives container restarts and rebuilds; the container runs as a non-root user.
* Scope is the home network; TLS and authentication for public/VPS exposure are deliberately deferred to a separate issue (#5).
